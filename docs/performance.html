1. Performance Overview

AgentBox ships as a zero-dependency landing page with 60+ JavaScript modules concatenated into a single bundle via build.js. The architecture uses IIFE modules, IntersectionObserver-based lazy initialization, and localStorage for state persistence. This guide covers how to keep load times fast as the module count grows.

Architecture Characteristics

  • Single-page — all content in index.html with no client-side routing
  • No framework overhead — vanilla JS IIFEs, no virtual DOM diffing
  • Concatenation bundler — build.js merges all modules into dist/bundle.js (no tree-shaking)
  • Lazy init — many modules defer initialization until their DOM section scrolls into view
  • Gzip — Nginx Docker config enables gzip for HTML, CSS, and JS

2. Core Web Vitals Targets

These are the targets AgentBox aims to hit, aligned with Google's Core Web Vitals thresholds:

Largest Contentful Paint (LCP)
< 2.5s
Hero section renders fast because it's static HTML
Interaction to Next Paint (INP)
< 200ms
All event handlers are lightweight synchronous operations
Cumulative Layout Shift (CLS)
< 0.1
No lazy-loaded images or injected ads that shift content
First Contentful Paint (FCP)
< 1.8s
CSS is inline or minimal; no render-blocking requests

3. Bundle Analysis

The build script (build.js) concatenates modules in dependency order into dist/bundle.js. Since there is no tree-shaking, every module is included regardless of whether the user scrolls to it.

Analyzing Bundle Size

# Build and measure
npm run build

# Quick size check (uncompressed vs gzip estimate)
ls -lh dist/bundle.js
gzip -k dist/bundle.js && ls -lh dist/bundle.js.gz && rm dist/bundle.js.gz

# Per-module size breakdown (approximate)
node -e "
  const fs = require('fs');
  const src = fs.readFileSync('dist/bundle.js', 'utf8');
  const parts = src.split(/\/\* === (.+?) === \*\//);
  const sizes = [];
  for (let i = 1; i < parts.length; i += 2) {
    sizes.push({ file: parts[i], kb: (parts[i+1].length / 1024).toFixed(1) });
  }
  sizes.sort((a, b) => b.kb - a.kb);
  sizes.forEach(s => console.log(s.kb.padStart(8) + ' KB  ' + s.file));
  console.log('Total:', (src.length / 1024).toFixed(1), 'KB');
"
💡 Tip

The biggest modules are typically chat-demo.js, pipeline-builder.js, and playground.js which contain large template strings. These are prime candidates for lazy loading.

Module Load Order

The concatenation order in build.js is critical. Dependencies must load before dependents:

  1. Foundation: storage.js → dom-utils.js → globals.js
  2. Templates: _typing-indicator-template.js
  3. Core sections: chat-demo, testimonials, pricing, FAQ, how-it-works, stats
  4. Interactive tools: calculator, capacity-planner, pipeline-builder, etc.
  5. Chrome/UX: site-nav, theme-toggle, scroll-progress, command-palette
  6. Bootstrap: init.js (must be last — wires everything together)

4. Lazy Loading Strategy

AgentBox uses IntersectionObserver to defer module initialization until the user scrolls near a section. This is the primary performance lever — the JS parses immediately but heavy DOM construction waits until needed.

How It Works

// Pattern used by most modules:
(function () {
  'use strict';

  function init() {
    // Heavy DOM construction, event binding, etc.
  }

  // Defer until section is visible
  var section = document.getElementById('my-section');
  if (!section) return;

  if ('IntersectionObserver' in window) {
    var observer = new IntersectionObserver(function (entries) {
      if (entries[0].isIntersecting) {
        observer.disconnect();
        init();
      }
    }, { rootMargin: '200px' });
    observer.observe(section);
  } else {
    // Fallback: initialize immediately
    init();
  }
})();

5. Critical Rendering Path

The critical rendering path for AgentBox's first paint:

1. HTML download + parse (index.html)
2. Inline CSS / <style> blocks (no external stylesheet blocking in dev)
   Production: styles.css (single file, gzipped)
3. Hero section renders (static HTML, no JS needed)
4. bundle.js downloads (deferred or at body end)
5. IIFE modules execute:
   a. storage.js, dom-utils.js, globals.js (fast, no DOM writes)
   b. theme-toggle applies saved theme (prevents FOUC)
   c. site-nav initializes
   d. IntersectionObservers registered for below-fold sections
6. User sees interactive hero + nav within ~1-2s
⚠️ Watch Out

Adding <script> tags in the <head> without defer or async will block the critical rendering path. Always load JS at the end of <body> or use defer.

6. Module Load Tiers

Organize modules into three tiers based on when they need to be active:

TierWhenExamplesBudget
T0 — Critical Before first paint storage, dom-utils, globals, theme-toggle, site-nav < 15 KB gzipped
T1 — Above-fold Within 1s of load chat-demo, hero stats, pricing, testimonials < 30 KB gzipped
T2 — Below-fold On scroll (IntersectionObserver) All interactive tools, tutorials, playground No hard limit

7. Caching & CDN

Nginx Cache Headers (Docker)

The Dockerfile's nginx config sets these cache policies:

# HTML: short cache, must revalidate
location ~* \.(html)$ {
    expires 1h;
    add_header Cache-Control "public, must-revalidate";
}

# Static assets: long cache with content-hash filenames
location ~* \.(js|css|png|jpg|svg|woff2)$ {
    expires 30d;
    add_header Cache-Control "public, immutable";
}

Cache-Busting Strategy

Since bundle.js doesn't include a content hash in its filename, cache invalidation relies on the HTML's 1-hour TTL. For production deployments:

# Option 1: Add version query string in index.html
<script src="dist/bundle.js?v=2.0.0"></script>

# Option 2: Modify build.js to include a hash
const crypto = require('crypto');
const hash = crypto.createHash('md5').update(bundle).digest('hex').slice(0, 8);
const outPath = path.join(distDir, `bundle.${hash}.js`);

CDN Recommendations

  • GitHub Pages — free, automatic CDN via Fastly; set Cache-Control via _headers file
  • Cloudflare — put in front of Docker deploy for edge caching + DDoS protection
  • Self-hosted — enable gzip and set Cache-Control: public, max-age=86400 for HTML, max-age=2592000, immutable for hashed assets

8. Image Optimization

AgentBox is primarily text and SVG-based, but if you add images:

  • Use loading="lazy" on all below-fold <img> tags
  • Specify width and height attributes to prevent CLS
  • Prefer SVG for icons and diagrams (already the norm in AgentBox)
  • Use WebP/AVIF with <picture> fallback for photographs
  • Keep hero images under 100 KB — they block LCP
<picture>
  <source srcset="hero.avif" type="image/avif">
  <source srcset="hero.webp" type="image/webp">
  <img src="hero.jpg" alt="AgentBox dashboard"
       width="1200" height="630" loading="eager">
</picture>

9. Runtime Performance

DOM Batch Writes

AgentBox modules should batch DOM mutations to avoid layout thrashing:

// BAD: read-write-read-write (forces multiple reflows)
var height = el.offsetHeight;
el.style.height = (height + 10) + 'px';
var width = el.offsetWidth;
el.style.width = (width + 10) + 'px';

// GOOD: batch reads, then batch writes
var height = el.offsetHeight;
var width = el.offsetWidth;
el.style.height = (height + 10) + 'px';
el.style.width = (width + 10) + 'px';

Event Delegation

Instead of attaching listeners to every button in a list, delegate to the parent:

// GOOD: single listener on parent
document.getElementById('feature-grid').addEventListener('click', function (e) {
  var card = e.target.closest('[data-feature]');
  if (card) handleFeatureClick(card.dataset.feature);
});

Animation Performance

  • Use transform and opacity for animations (GPU-composited, no layout)
  • Avoid animating width, height, top, left (triggers layout)
  • Use will-change: transform sparingly — only on elements about to animate
  • Prefer CSS transitions over JS setInterval animations

localStorage Performance

The StorageUtil wrapper is synchronous and touches the main thread. Avoid calling it in hot loops:

// BAD: read storage on every scroll event
window.addEventListener('scroll', function () {
  var prefs = StorageUtil.getJSON('prefs', {});  // synchronous I/O
  // ...
});

// GOOD: cache in memory, write on debounced save
var prefs = StorageUtil.getJSON('prefs', {});
window.addEventListener('scroll', debounce(function () {
  StorageUtil.setJSON('prefs', prefs);
}, 1000));

Performance API

// Measure module init time
performance.mark('chat-demo-start');
ChatDemo.init();
performance.mark('chat-demo-end');
performance.measure('ChatDemo init', 'chat-demo-start', 'chat-demo-end');

// Log all module timings
performance.getEntriesByType('measure').forEach(function (m) {
  console.log(m.name + ': ' + m.duration.toFixed(1) + 'ms');
});

Bundle Size Monitoring

Add a size check to CI to prevent regressions:

# .github/workflows/ci.yml addition:
- name: Bundle size check
  run: |
    npm run build
    SIZE=$(stat -f%z dist/bundle.js 2>/dev/null || stat -c%s dist/bundle.js)
    MAX=524288  # 512 KB limit
    echo "Bundle: $SIZE bytes (max: $MAX)"
    if [ "$SIZE" -gt "$MAX" ]; then
      echo "::error::Bundle exceeds 512 KB limit!"
      exit 1
    fi

11. Docker & Nginx Tuning

Gzip Configuration

The default Dockerfile enables gzip but can be tuned further:

# Already enabled in Dockerfile nginx config:
gzip on;
gzip_types text/html text/css application/javascript text/plain;
gzip_min_length 256;

# Additional optimizations:
gzip_comp_level 6;          # Balance compression ratio vs CPU
gzip_vary on;               # Serve different content to gzip-capable clients
gzip_static on;             # Serve pre-compressed .gz files if they exist

Pre-Compression at Build Time

# Add to Dockerfile build stage or CI:
RUN gzip -k -9 /usr/share/nginx/html/*.js \
    /usr/share/nginx/html/*.css \
    /usr/share/nginx/html/*.html

# Then enable gzip_static in nginx:
gzip_static on;

Pre-compression avoids CPU cost on every request. Combined with gzip_static on, Nginx serves the .gz file directly when the client supports gzip.

HTTP/2 Server Push (advanced)

# If running behind a reverse proxy that supports HTTP/2:
location / {
    http2_push /dist/bundle.js;
    http2_push /styles.css;
}

🚀 Quick Wins

The three highest-impact optimizations you can do today:

  1. Pre-compress assets at build time with gzip -9 and enable gzip_static — saves CPU on every request
