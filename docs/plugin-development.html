1. Module Architecture Overview

AgentBox uses a zero-dependency, IIFE-based module system. Each module is a self-contained file under src/modules/ that exposes its API via an immediately-invoked function expression (IIFE). Modules are concatenated by build.js into the final dist/ bundle.

Key Principles

  • No external dependencies — everything is vanilla JS (ES5-compatible where possible)
  • DOM-scoped initialization — modules bind to specific container selectors, never the full document
  • Graceful degradation — modules must handle missing DOM elements without throwing
  • Accessibility-first — ARIA attributes, keyboard navigation, and focus management are mandatory
  • Theme-aware — use CSS custom properties from :root, never hardcoded colors

Directory Layout

src/
  modules/
    your-module.js ← module implementation
__tests__/
  your-module.test.js ← Jest + jsdom tests
index.html ← section markup for the module
styles.css ← component styles

2. Scaffolding a New Module

Every module follows the same IIFE pattern. Here’s the canonical template:

// ---------------------------------------------------------------------------
// MyWidget Module
// ---------------------------------------------------------------------------

var MyWidget = (function () {
  'use strict';

  // ── Private state ──────────────────────────────────────────────
  var _container = null;
  var _state = { initialized: false };

  // ── Private helpers ────────────────────────────────────────────
  function _render() {
    if (!_container) return;
    // Build or update DOM content
  }

  function _handleClick(e) {
    var target = e.target.closest('[data-mywidget-action]');
    if (!target) return;
    var action = target.getAttribute('data-mywidget-action');
    // Handle actions...
  }

  function _handleKeydown(e) {
    if (e.key === 'Enter' || e.key === ' ') {
      e.preventDefault();
      _handleClick(e);
    }
  }

  // ── Public API ─────────────────────────────────────────────────
  function init(containerSelector) {
    _container = typeof containerSelector === 'string'
      ? document.querySelector(containerSelector)
      : containerSelector;
    if (!_container) return; // graceful exit if section not on page

    _container.addEventListener('click', _handleClick);
    _container.addEventListener('keydown', _handleKeydown);
    _state.initialized = true;
    _render();
  }

  function destroy() {
    if (!_container) return;
    _container.removeEventListener('click', _handleClick);
    _container.removeEventListener('keydown', _handleKeydown);
    _container = null;
    _state.initialized = false;
  }

  return {
    init: init,
    destroy: destroy
  };
})();
Tip: Always include a destroy() method. It’s needed for testing (cleanup between test cases) and for SPA-like page transitions if the landing page ever gets client-side routing.

3. Lifecycle & Initialization

Modules are initialized from the page-level script block at the bottom of index.html. The standard boot sequence is:

document.addEventListener('DOMContentLoaded', function () {
  // Core modules (always present)
  SiteNav.init();
  ThemeToggle.init();

  // Feature modules (initialize only if their section exists)
  if (document.getElementById('faqSection')) FAQ.init('#faqSection');
  if (document.getElementById('myWidgetSection')) MyWidget.init('#myWidgetSection');
});

Initialization Contract

RuleRationale
Check container exists before bindingNot all pages include all sections
Never throw from init()One broken module must not block others
Use event delegation on containerReduces listener count, handles dynamic content
Support both selector string and ElementFlexibility for testing and programmatic use

4. DOM Conventions & Selectors

Naming Conventions

  • Section IDs: camelCase with Section suffix — id="myWidgetSection"
  • CSS classes: kebab-case with module prefix — .my-widget-item, .my-widget-active
  • Data attributes: data-{module}-{purpose} — data-mywidget-action="toggle"
  • ARIA: Use semantic roles + aria-expanded, aria-controls, aria-live as needed

Example Section Markup

<section id="myWidgetSection" class="section" aria-labelledby="myWidgetHeading">
  <h2 id="myWidgetHeading">My Widget</h2>
  <div class="my-widget-container">
    <button class="my-widget-btn"
            data-mywidget-action="activate"
            aria-expanded="false"
            aria-controls="myWidgetPanel">
      Open Widget
    </button>
    <div id="myWidgetPanel" class="my-widget-panel" role="region" hidden>
      <!-- Dynamic content rendered by module -->
    </div>
  </div>
</section>
Never use document.querySelectorAll without scoping. Always query within the module’s container element to avoid cross-module interference and improve performance on large pages.

5. State Management

AgentBox modules use a simple closure-based state pattern. For modules that need persistence across page loads, use the shared storage.js utility:

// Reading persisted state (uses localStorage with JSON serialization)
var Storage = window.AgentBoxStorage || { get: function() { return null; }, set: function() {} };

function init(container) {
  _container = document.querySelector(container);
  if (!_container) return;

  // Restore previous state if available
  var saved = Storage.get('mywidget-state');
  if (saved) {
    _state = Object.assign(_state, saved);
    _render(); // Reflect restored state immediately
  }
}

function _persist() {
  Storage.set('mywidget-state', { activeTab: _state.activeTab });
}

State Rules

  • Keep state minimal — only persist user preferences, not computed/transient values
  • Always validate restored state (schema may have changed between versions)
  • Use a unique storage key prefixed with your module name
  • Respect the user’s prefers-reduced-data / cookie consent before writing to storage

6. Accessibility Requirements

Required All modules must meet WCAG 2.1 AA. The CI pipeline runs automated checks.

Mandatory Accessibility Features

FeatureImplementation
Keyboard navigationAll interactive elements reachable via Tab; actions triggered by Enter/Space
Focus managementVisible focus ring (:focus-visible); focus trapped in modals/overlays
ARIA statesaria-expanded, aria-selected, aria-hidden updated on interaction
Screen reader announcementsUse aria-live="polite" for dynamic content updates
Reduced motionRespect prefers-reduced-motion: reduce — disable animations
Color contrastMinimum 4.5:1 for text, 3:1 for large text and UI elements

Reduced Motion Pattern

var _prefersReducedMotion = window.matchMedia
  ? window.matchMedia('(prefers-reduced-motion: reduce)').matches
  : false;

function _animate(el, property, from, to, duration) {
  if (_prefersReducedMotion) {
    // Skip animation, apply final state immediately
    el.style[property] = to;
    return;
  }
  // ... animation logic
}

7. Theme Integration

AgentBox supports light and dark themes via CSS custom properties. The ThemeToggle module manages the data-theme attribute on <html>.

Using Theme Variables in CSS

.my-widget-panel {
  background: var(--bg-card);
  border: 1px solid var(--border);
  color: var(--text);
}
.my-widget-panel .label {
  color: var(--text-dim);
}
.my-widget-panel .highlight {
  color: var(--accent);
}

Available CSS Variables

VariableDark ValueUsage
--bg#0f1117Page background
--bg-card#1a1d28Card/panel surfaces
--bg-code#252830Code block backgrounds
--text#e0e0e8Primary text
--text-dim#8b8fa0Secondary/muted text
--accent#4a9effLinks, highlights, primary actions
--border#2d3040Borders and dividers
--green#4ade80Success states
--yellow#facc15Warning states
--red#f87171Error/danger states
Tip: Never use color: white or background: #1a1d28 directly. Always reference the CSS variable so themes switch correctly.

8. Testing Your Module

Tests live in __tests__/your-module.test.js and run with Jest + jsdom. The test environment simulates a browser DOM.

Test File Template

/**
 * @jest-environment jsdom
 */

'use strict';

describe('MyWidget', () => {
  let container;

  beforeEach(() => {
    // Set up minimal DOM structure the module expects
    document.body.innerHTML = `
      <section id="myWidgetSection">
        <button data-mywidget-action="toggle" aria-expanded="false"
                aria-controls="panel1">Toggle</button>
        <div id="panel1" class="my-widget-panel" hidden></div>
      </section>
    `;
    container = document.getElementById('myWidgetSection');

    // Load the module (IIFE assigns to global)
    require('../src/modules/your-module.js');
  });

  afterEach(() => {
    // Clean up to prevent test leakage
    if (typeof MyWidget !== 'undefined' && MyWidget.destroy) {
      MyWidget.destroy();
    }
    document.body.innerHTML = '';
  });

  test('init does not throw when container is missing', () => {
    expect(() => MyWidget.init('#nonexistent')).not.toThrow();
  });

  test('click toggles aria-expanded', () => {
    MyWidget.init('#myWidgetSection');
    const btn = container.querySelector('[data-mywidget-action]');
    btn.click();
    expect(btn.getAttribute('aria-expanded')).toBe('true');
  });

  test('keyboard Enter triggers action', () => {
    MyWidget.init('#myWidgetSection');
    const btn = container.querySelector('[data-mywidget-action]');
    const event = new KeyboardEvent('keydown', { key: 'Enter', bubbles: true });
    btn.dispatchEvent(event);
    expect(btn.getAttribute('aria-expanded')).toBe('true');
  });

  test('destroy removes event listeners', () => {
    MyWidget.init('#myWidgetSection');
    MyWidget.destroy();
    const btn = container.querySelector('[data-mywidget-action]');
    btn.click();
    // Should remain unchanged after destroy
    expect(btn.getAttribute('aria-expanded')).toBe('false');
  });
});

Running Tests

# Run all tests
npm test

# Run with coverage
npm run test:coverage

# Run a single test file
npx jest __tests__/your-module.test.js --verbose

What to Test

  • Initialization: Handles missing containers, duplicate init calls
  • User interaction: Click, keyboard (Enter, Space, Escape, Arrow keys)
  • ARIA state: Attributes update correctly after interactions
  • Edge cases: Empty data, single items, maximum items
  • Cleanup: destroy() removes listeners and resets state
  • Accessibility: Focus management, aria-live regions update

9. Build Integration

The build system (build.js) concatenates modules into a single bundle. To include your module:

  1. Place your module file at src/modules/your-module.js
  2. Add the HTML section to index.html with the appropriate id
  3. Add component styles to styles.css (grouped by module)
  4. Add initialization call to the DOMContentLoaded handler in index.html
  5. Run npm run build to verify the bundle generates cleanly

Build Verification

# Build the bundle
npm run build

# Verify no syntax errors in the concatenated output
node -c dist/agentbox.js

# Run the full test suite
npm test

10. Pre-Merge Checklist

Before pushing a new module, verify:

  • ☐ Module follows IIFE pattern with init() and destroy()
  • ☐ Graceful no-op when container element is absent
  • ☐ Event delegation used (listeners on container, not individual elements)
  • ☐ All interactive elements have keyboard support (Enter + Space)
  • ☐ ARIA attributes present: role, aria-expanded, aria-controls, aria-label as needed
  • ☐ Reduced motion respected (prefers-reduced-motion check)
  • ☐ Only CSS custom properties used for colors (no hardcoded hex in JS)
  • ☐ Test file created with ≥80% branch coverage for the module
  • ☐ npm test passes with no new warnings
  • ☐ npm run build succeeds and node -c dist/agentbox.js passes
  • ☐ HTML section includes aria-labelledby pointing to heading
  • ☐ No console.log calls (use conditional debug logging if needed)
  • ☐ CSP-compatible: no inline scripts, no eval(), no external resource loads
  • ☐ Storage keys prefixed with module name to avoid collisions
