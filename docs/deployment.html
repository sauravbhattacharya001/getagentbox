Prerequisites

Before deploying, build the production bundle:

# Install dependencies
npm install

# Build the production bundle (dist/bundle.js)
npm run build

# Run tests to verify everything works
npm test

The build step bundles all 59 source modules from src/ into a single dist/bundle.js. The deployment artifacts are:

GitHub Pages (Recommended)

The repository includes a pre-configured .github/workflows/pages.yml workflow that deploys automatically on push to master.

How It Works

  1. Push changes to the master branch
  2. The pages.yml workflow triggers automatically
  3. It assembles a _site/ directory with all required files
  4. The actions/deploy-pages action publishes to GitHub Pages

First-Time Setup

  1. Go to Settings → Pages in your repository
  2. Under Source, select GitHub Actions
  3. Push any change to master to trigger the first deploy
  4. Your site will be live at https://<username>.github.io/getagentbox/
Tip: The workflow only triggers on changes to *.html, *.css, *.js, vendor/**, or docs/** files — non-code changes (README, tests) won't trigger a redeploy.

Docker

The included multi-stage Dockerfile validates HTML, then serves via a hardened nginx container running as a non-root user.

Quick Start

# Build the image
docker build -t agentbox .

# Run on port 8080
docker run -d -p 8080:8080 --name agentbox agentbox

# Verify it's running
curl http://localhost:8080/healthz
# → ok

Docker Compose

# docker-compose.yml
services:
  agentbox:
    build: .
    ports:
      - "8080:8080"
    restart: unless-stopped
    read_only: true
    tmpfs:
      - /var/cache/nginx:size=10m
      - /var/run:size=1m
    security_opt:
      - no-new-privileges:true
    deploy:
      resources:
        limits:
          memory: 64M
          cpus: '0.25'

Pre-Built Images

The CI/CD pipeline builds and pushes Docker images to GitHub Container Registry on every push to master:

# Pull the latest image
docker pull ghcr.io/sauravbhattacharya001/getagentbox:latest

# Or pin a specific version
docker pull ghcr.io/sauravbhattacharya001/getagentbox:sha-abc1234

Security Features

  • Multi-stage build — validation artifacts don't ship in production
  • Runs as non-root user (app:1001)
  • Comprehensive security headers (CSP, HSTS, X-Frame-Options, CORP, COEP, COOP)
  • Gzip compression enabled
  • Built-in health check endpoint at /healthz
  • Dotfile access denied

Netlify

  1. Connect your GitHub repository in the Netlify dashboard
  2. Set Build command: npm run build
  3. Set Publish directory: . (root)
  4. Deploy

Add a netlify.toml for headers and redirects:

[build]
  command = "npm run build"
  publish = "."

[[headers]]
  for = "/*"
  [headers.values]
    X-Frame-Options = "DENY"
    X-Content-Type-Options = "nosniff"
    Referrer-Policy = "strict-origin-when-cross-origin"
    Content-Security-Policy = "default-src 'self'; script-src 'self'; style-src 'self';"

[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200

Self-Hosted (nginx)

For full control, serve AgentBox from your own nginx instance.

Minimal nginx Configuration

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    root /var/www/agentbox;
    index index.html;

    # SSL (use certbot or your CA)
    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    # Security headers
    add_header X-Frame-Options "DENY" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self'; frame-ancestors 'none';" always;

    # Gzip
    gzip on;
    gzip_types text/html text/css application/javascript;
    gzip_min_length 256;

    # Cache static assets
    location ~* \.(js|css)$ {
        expires 7d;
        add_header Cache-Control "public, immutable";
    }

    # SPA fallback
    location / {
        try_files $uri $uri/ /index.html;
    }

    # Deny dotfiles
    location ~ /\. { deny all; }
}

Deployment Script

#!/bin/bash
set -euo pipefail

DEPLOY_DIR="/var/www/agentbox"
REPO="https://github.com/sauravbhattacharya001/getagentbox.git"

# Clone or pull latest
if [ -d "$DEPLOY_DIR/.git" ]; then
    cd "$DEPLOY_DIR" && git pull origin master
else
    git clone --depth 1 "$REPO" "$DEPLOY_DIR"
fi

# Build
cd "$DEPLOY_DIR"
npm install --production
npm run build

# Set permissions
chown -R www-data:www-data "$DEPLOY_DIR"

# Reload nginx
nginx -t && systemctl reload nginx

echo "Deployed successfully!"

Environment Configuration

AgentBox is a static site with no server-side configuration. Runtime behavior is controlled through:

Analytics (GoatCounter)

Privacy-friendly analytics are enabled by default via the vendored GoatCounter script. To change the analytics endpoint, update the data-goatcounter attribute in index.html:

<script data-goatcounter="https://YOUR-SITE.goatcounter.com/count"
        async src="vendor/count.js"></script>

To disable analytics entirely, remove both the GoatCounter <script> tag and the cookie consent script.

Content Security Policy

The CSP is defined in two places that must stay in sync:

  • index.html — <meta http-equiv="Content-Security-Policy">
  • Dockerfile — nginx add_header Content-Security-Policy

If you add external resources (fonts, CDN scripts), update both locations.

CDN & Caching

AgentBox is well-suited for CDN caching since all content is static. Recommended cache headers:

File TypeCache DurationRationale
*.html1 hourContent may change frequently
dist/bundle.js7 daysChanges only on rebuild
styles.css7 daysChanges only on rebuild
vendor/*30 daysThird-party, versioned with SRI
Tip: The vendor scripts use Subresource Integrity (SRI) hashes, so they can be cached aggressively — the browser will reject tampered content regardless of cache duration.

Monitoring & Health Checks

Docker Health Check

The Docker image includes a built-in health check on /healthz:

# Check container health
docker inspect --format='{{.State.Health.Status}}' agentbox
# → healthy

# Manual check
curl -s http://localhost:8080/healthz
# → ok

Uptime Monitoring

Point your uptime monitor (UptimeRobot, Pingdom, etc.) at:

  • HTTP check: GET / — expect 200
  • Docker: GET /healthz — expect 200 with body "ok"
  • Content check: Verify response contains AgentBox

Troubleshooting

Blank page after deploy

Check that dist/bundle.js was built and included. Run npm run build before deploying. Verify the browser console for 404 errors on script loads.

CSP errors in console

If you see Refused to load the script... errors, your CSP doesn't allow the resource. Update the CSP in both index.html and your server config (Dockerfile/nginx).

GitHub Pages shows 404

  • Verify Pages source is set to "GitHub Actions" (not "Deploy from branch")
  • Check the Actions tab for workflow failures
  • Ensure the repo has Pages enabled in Settings

Docker container exits immediately

# Check logs
docker logs agentbox

# Common cause: port conflict
# Solution: use a different host port
docker run -d -p 9090:8080 --name agentbox agentbox

Assets not loading with custom domain

All asset references in AgentBox are relative, so custom domains work out of the box. If assets fail to load, check that your CDN/proxy is forwarding the correct path prefix.

Note: The GoatCounter analytics script requires a connect-src CSP directive allowing https://agentbox.goatcounter.com. If you change the GoatCounter endpoint, update the CSP accordingly.
