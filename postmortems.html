API Gateway Outage — Complete Service Disruption

Critical ⏱ 42 min Mar 15, 2026 ▼

Summary

A misconfigured rate-limiting rule in the API gateway caused all incoming requests to be rejected with 429 status codes. The issue was triggered during a routine configuration deployment at 14:22 UTC.

Root Cause

The rate-limiting configuration used a YAML anchor that referenced a staging value of 0 instead of the production value of 10000. The config validation pipeline did not check for zero-value rate limits.

Action Items

  • ✅ Add config validation rule to reject zero-value rate limits
  • ✅ Implement canary deployments for gateway config changes
  • ✅ Add pre-deployment smoke test that sends a real request
  • ✅ Remove YAML anchors from production config files

Delayed Message Delivery — Telegram Webhook Queue Backup

Major ⏱ 28 min Mar 8, 2026 ▼

Summary

Messages sent to AgentBox via Telegram experienced delays of 2–8 minutes due to a webhook processing queue backup. The queue worker ran out of memory after processing a series of large image attachments.

Impact

Root Cause

The webhook worker loaded entire image payloads into memory for processing. A burst of high-resolution images (10+ MB each) caused the worker's heap to exceed its limit, triggering repeated garbage collection pauses.

Action Items

  • ✅ Stream image payloads to disk instead of buffering in memory
  • ✅ Add per-message memory budget with graceful rejection
  • ✅ Implement horizontal auto-scaling for webhook workers
  • ⬜ Add queue depth monitoring with auto-scale trigger

Root Cause

A composite index on (user_id, created_at) was missing from the events table. The query planner fell back to a sequential scan once the table exceeded a size threshold.

Action Items

  • ✅ Add missing composite index
  • ✅ Add slow-query alerting (>500ms) for all dashboard endpoints
  • ⬜ Schedule quarterly index review for high-growth tables

Authentication Failures — OAuth Token Refresh Bug

Major ⏱ 22 min Feb 14, 2026 ▼

Summary

Users who had been logged in for more than 24 hours were unable to perform actions requiring authentication. The OAuth token refresh endpoint was returning expired tokens due to a clock skew between auth servers.

Root Cause

One of three auth servers had drifted 45 seconds ahead due to a failed NTP sync. Tokens issued by this server had an iat (issued-at) timestamp in the future, causing other servers to reject them as invalid.

Action Items

  • ✅ Add NTP sync monitoring with alerting on >5s drift
  • ✅ Add 60-second clock skew tolerance to token validation
  • ✅ Implement forced NTP sync on auth server startup
